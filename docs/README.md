# 项目文档入口 / AI 接手指南

最后整理：2026-09-29。项目：星熠传媒内部管理系统（仓库名 manager）。

本目录是跨 AI、跨会话交接的项目内资料。**先读当前文档，再按需查历史；不要从旧聊天或旧版方案推断现在的权限。** 文档中的“已上线”必须有发布记录支持；建议、已开发、已测试与已上线是不同状态。

## 新接手的阅读顺序

1. 根目录 [AGENTS.md](../AGENTS.md)：每次开发必须执行的规则，含文档同步要求。
2. [当前进度与交接点](current-status.md)：当前线上版本、最近交付、当前任务、下一步与验证范围。
3. [当前业务规则与权限](business-rules.md)：以最终确认的岗位分工为准，尤其直播中控与导粉专员。
4. [开发决策登记](decisions.md)：为什么这样设计、哪些旧方案被替代。
5. [架构与代码地图](architecture.md)、[数据模型](data-model.md)：定位要修改的代码与关联影响。
6. [开发与验证规范](development-guide.md)：小步修改、隔离测试、验收标准、文档维护流程。
7. 涉及上线再读 [运维操作手册](operations.md) 与 [实际发布记录](deployment.md)。
8. [已知限制与待办](known-issues.md)、[变更日志](CHANGELOG.md)：不能把历史通过或未来意向当成当前完整能力。

## 信息优先级与冲突处理

- 最新用户明确确认的要求决定产品方向；较早同主题决定被后续决定替代。
- 代码、数据库迁移和实际部署核验说明“目前做到了什么”，不能被文档中的愿望覆盖。
- 本目录的当前规则用于日常接手，原有专题文档保留历史背景；部署日志按日期和实际证据阅读，不按段落位置判断新旧。
- 发现要求与实现不一致：记录到 known-issues.md，说明证据与影响；不要静默改权限、批量改正式数据或把尚未实现写成已完成。
- 本轮文档依据本地代码、已有发布记录和当前会话整理。除最近一次发布已核验的内容外，没有重新逐项验收所有历史功能，也没有重新登录生产采集业务数据。
