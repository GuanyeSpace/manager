# 当前业务规则与权限

有效快照：2026-09-29。产品事实以最终用户确认为方向，以服务端实现说明当前边界；具体组合例外见本文和 known-issues.md。素材管理、统一巡检等旧设计已失效；直播填写岗位以D056规则为准。

## 1. 业务对象和术语

- 公司内有多个分公司。老板跨公司查看管理；分公司负责人是 Branch.managerId 指定的附加身份，不是独立 Role 枚举。
- “抖音账号”是平台账号档案；“直播间”是人员/场地/物资的组织对象；“直播场次”是一段真实开播及前后执行过程；“上班记录”可以跨日并包含多个账号多场直播。
- 员工身份可以包含多个岗位。界面名称为“直播中控”“导粉专员”“打粉数据”。代码中的 CONTROLLER、monetization 等历史标识不用为改中文名称而改库。
- 系统记录任务和统计，不操作抖音开关播，也不自动发卡片、礼物、评论或话术。

## 2. 员工、分公司和职责

- 员工可同时选多个岗位：老板、运营、直播中控、导粉专员、小助理、主播、财务。拥有枚举不等于该岗位已有完整专用工作台。
- 有效岗位为 User.role 与 User.roles 合集，禁止只比较旧单岗位字段。
- 老板登录优先进入 /boss，其次中控 /controller，其次导粉 /leads，其余 /wip。顶部工作台入口体现兼任，切换入口不结束直播或解除认领。
- 当前只有老板管理员工和分公司、指定负责人；负责人仅管理业务权限范围内的本分公司资料，不能据此推断拥有员工管理能力。
- 员工离职不删除档案，立即撤销会话；复职保留历史。至少保留一个在职老板；老板不能自行离职或移除自己的老板职责。
- 增加岗位不强制解除原关系；撤岗、调公司、离职需要检查职责交接。移除导粉职责撤销数据操作资格但保留历史认领。
- 新用户及重置密码后强制改密。输入校验失败不能清空整张用户表单。并发旧表单不能覆盖新岗位或新业务版本。

## 3. 账号与主播、直播间关系

- 账号字段：抖音号唯一、名称、主页链接、实名人、绑定号码、用途、备注、状态、分公司及三类负责人。账号管理列表在抖音号后显示已有实名人，空值显示“未填写”；仍仅展示当前有权查看的账号，旧负责人历史不新增实名信息。
- 账号列表增加“所在手机”，隐藏分公司与运营列（详情/编辑保留）。所在手机来自实际登录关联PhoneAccountLogin，按编号列出有权查看的手机，可点击详情并按来源返回；不从绑定SIM推断手机。关联在手机编辑页“登录抖音号”维护，无可见关联显示“未登记或无可见手机”。
- 一个账号同时属于一家分公司；账号运营、中控、主播分别最多一人。中控、运营和主播均可空；老板可兼任。
- 一个直播间可以关联多个抖音账号；一个账号同时最多关联一个直播间；一个直播间可有多个主播，一个主播可在多个直播间。
- 主播是员工角色，不新增一套重复主播人员身份。修改主播相关中控/运营通过其关联的具体抖音账号完成；同一主播不同账号可以有不同人员。
- 跨公司调拨由老板执行；检查接收方人员、直播间、号码、实际登录手机等关系兼容性，不能把关联物资偷偷跨公司搬走。
- 账号状态支持启用、停用、封禁；封禁显示预计解封日期（YYYY-MM-DD），未知可留空显示待定。封禁禁止新准备/开播，预计日期到期不自动恢复，需原有账号管理权限人员确认后启用。换绑手机号不得改变封禁及日期；历史状态和预计日期留存。
- 账号准备中或直播中不能交接、停用、标记封禁或调拨；先结束/取消当前执行。当前账号资料和 AccountRecord 历史分开。
- 旧负责人仅看原职责范围内的账号历史，不因历史记录拿到当前私密资料。账号历史不存实名人、号码和平台凭证。
- 无主播账号可存档（例如辅助用途），但当前开场服务要求账号已启用、分公司启用、绑定主播及中控且已保存流程，不为无主播账号伪造直播。

## 4. 直播中控完整工作流

### 4.1 登录和上班

- 不做排班展示；当天安排在微信群或口头通知，中控自行选账号。
- 点击“开始上班”建立检查中记录（0/4），尚未到岗成功；共享电脑、声音、画面、网络检查归这次上班。跨凌晨不自动新建上班记录，不将凌晨继续工作视为新一天首场。
- 同一登录账号同时只有一条未结束上班记录。补填到岗时间或更正必须说明原因并校验时间范围。
- 提前半小时为管理关注信息：按该次上班首场实际开播与登记上班时间计算（另展示首次全部检查完成时间），当前不自动处罚或强制拒绝未提前半小时的人。
- 不每场重复确认共享设备检查；声音、画面、网络未确认正常则不能实际开播，修复后可重新检查。

- 四项初始不默认正常；正常勾选完成即保存，异常备注必填。四项无论正常/异常均确认后自动到岗成功。修改结果留痕且不重置首次完成时间；失败保留输入。
- 电脑检查软件可用；声音使用录屏测试；画面检查摄像机/手机、灯光及贴片；网络人工确认直播伴侣测速大于50 Mb，不自动测速。

### 4.2 选择账号和准备

- 选择可负责的账号，在开播前选择本场中控后点击一次“确认”即创建本场记录。即使未正常开播，也保留记录。
- 本场实际中控默认本人，可以选该账号本分公司在职员工，含运营、负责人、其他临时代控员工；老板自己执行有相应跨公司例外。
- 登录操作者与实际中控分别留快照。选择某人为实际中控不会授予他新账号权限，也不代表中途会话交接。
- 每场前检查所用账号、贴片、直播保镖设置等账号专属事项，由运营或负责人配置。
- 开播前清单必须全部勾选完成，取消原因放行；声/画/网硬条件仍不能绕过。
- 无法开播：记录原因类型、详细原因、截图；不再填写预计恢复日期，历史日期保留，结果为“未正常开播”。不进入导粉认领池。

### 4.3 开播中

- 一个中控同一时间只能负责一场直播。按登录人、实际中控、账号同时占用与历史时间范围检查；多个准备或待收尾场次不等于允许多场同时直播。
- 实际开播后不能换中控；归档更正是留痕纠错，不是直播中换岗。
- 三阶段事项仅显示完成复选框与完成时间；直播表展示时间、工作内容、完成情况。系统记点击时刻，不由员工手写完成时间。
- 定时事项精确到分钟和秒；口令/随时执行事项不设固定提醒。过时仍可补做。
- 定时提醒不发声、非阻挡，同时间合并；关闭提醒不代表完成。没有全局强制每 15 分钟巡检，按账号配置。
- 当前阶段只可勾选或撤销，重新勾选记录新时间；其他阶段只读，归档纠错通过更正入口。旧异常/不适用和备注保留，但不算已完成。
- 违规记录原因并上传截图；异常中断也必须上传截图，进入收尾。重新开播必须新建一场。

### 4.4 下播、收尾与结束上班

- 下播记录实际时间；正常下播允许直播清单未完成且无需说明，异常下播原因和截图必填。历史未完成项不自动补成完成。
- 下播清单全部完成后，一次填写是否异常并收尾；异常可多选违规/其他异常，说明必填，含违规必须有截图。已记录的异常下播原因与截图带入，保留其他异常标记，可补违规；误报通过收尾后的更正入口处理。收尾、类型、说明、截图关联同事务保存。
- 默认导粉模式下，中控不录入或查看统计；D056中控模式的新场次允许中控维护本场直播数据，提交后才能收尾，仍禁止查看打粉数据。
- 允许先开始下一场准备、稍后补前场收尾；结束上班前本人准备中、直播中、待收尾必须处理完，包含有关联的旧待办。
- 收尾完成后可按原执行权限更正，说明原因，留前后值、操作人、时间；交接后原中控历史通常只读，老板可处理历史更正。
- 老板只需能看记录，不设计逐场审核、批准或必须即时通知老板。

- 普通下班须四项检查完成、不可更改的服务器计时起点满8小时、无未收尾场次。跨日连续计时；补登/更正登记时间不能绕过。
- 未满8小时可独立“提前下班”，必填原因并留标记/审计，不需审批；仍要求四项完成及全部场次收尾。历史已结束记录不重新判定，旧未结束记录以createdAt计时，不补造检查完成时间。

### 4.5 截图、话术和流程

- 未正常开播、异常中断、有违规必须截图，可多张；当前每次 1–6 张，单张不超过 5MB，总计不超过 20MB，PNG/JPG/WebP。
- 截图私有持久存储，按场次历史权限读取；更正补图不覆盖或删除原图。
- 话术分类：福袋、人设、进群、关注、其他。可多条，支持复制。
- 中控只能编辑话术，不能改流程。场中编辑话术同时更新本场与账号，以后新场沿用；其他历史场次仍用原快照。
- 流程由老板、本公司负责人、绑定运营配置；支持阶段内拖动和按钮排序、复制/批量应用，可分别选择阶段与话术；目标以后独立维护。
- 账号流程改动不重排已创建场次的事项索引。未配置流程须先由有权限的人保存。
- 素材在员工电脑，系统移除素材管理/复制/展示入口；保留历史 JSON 中 materials 防止数据损失。

## 5. 导粉专员工作流

- 独立岗位，可兼任直播中控；员工执行本场中控时可以同时为其他直播间导粉。
- 不固定账号负责人关系；按场认领，一人同时多场，每场只允许一名专员。
- 只认领本公司符合条件的已实际开播场次：直播中、待收尾、已收尾均可，无时限自动剔除。准备中、未正常开播、取消准备不出现。已实际播过的异常中断可以认领。
- 导粉上线前的旧场次 leadEligible=false，不自动放进认领池；已有历史报表也不重复认领。
- 发卡片时机和频率由人员自行决定，不记录发卡动作，不实现自动发送。
- 认领前只看场次基本信息；本人认领后填报直播指标、进群/链接点击/后端加人/后端有效人数。
- 后端数据通常下播后半小时确定，但允许晚填和跨天补齐，不处罚、不阻止认领下一场。
- 草稿允许未填，空白和 0 不同；全部必需指标填齐、实际下播、时长有效才提交完成。完成后可更正但必须说明原因，不能退回缺项草稿。
- 不提供普通交接。误认领由老板或该场原分公司负责人填原因纠正，数据保留、原人立即失权。离职未补数据由负责人维护。
- 专员只能改本人认领；运营只读负责账号的数据；老板/有权限负责人可改范围内全部，所有变更留谁改了什么。
- 专员无删除权；老板/负责人可带原因整场软删除/恢复，认领与执行记录保留。新流程不能走旧报表入口绕过状态、审计和权限。
- D051移除长按与带货输入，旧 longPressCount、hasSales、salesGmv 不删除、不归零，只在历史字段折叠区展示。新旧场次均不再因这些隐藏字段待补；待收尾和已删除状态仍提示。

## 6. 数据统计口径

| 字段/指标 | 当前口径 |
| --- | --- |
| 直播数据 | 时长、曝光、进房、平均在线、最高在线、人均停留、评论人数、点赞次数、新增粉丝、分享次数、加粉丝团人数；账号/开播时间/场次沿用执行记录 |
| 观众画像 | 女性比例、31–40岁比例，输入0–100百分数，可带%，最多两位小数 |
| 人均停留 | 分钟，最多两位小数；存整数百分之一分钟 |
| 时长 | 粘贴中文时长如1小时1分钟18秒，可省略零单位；保存总秒数；必须大于零 |
| 打粉数据 | 进粉丝群、链接点击、后端加人、后端有效人数；多群按场次汇总 |
| 场观 | 沿用同场直播数据进房人数；跨场相加不是去重观众 |
| 后端有效人数 | 不得大于后端加人数，不自动计算收入 |
| 进房率 / 粉丝转化率 | 进房÷曝光 / 新增粉丝÷进房 |
| 场观进群率 / 链接点击率 | 进群÷进房 / 链接点击÷进群 |
| 后端加人率 / 后端有效率 | 后端加人÷进群 / 后端有效÷后端加人 |
| 场观加人率 / 点击加人率 | 后端加人÷进房 / 后端加人÷链接点击 |

D051替代旧新增率、点击率分母及长按口径。所有页面含历史报表均按以上公式实时显示，不改历史原始人数。比例百分数四舍五入两位小数；分子或分母空白、分母零显示“—”，分子零/分母正数显示“0.00%”。平均在线不得大于最高在线。

新导粉首次提交完成必须填齐全部手填项含两项画像；草稿空白表示未确定、0表示确实没有。实际下播、时长结束时间不晚于当前服务器时间后才能完成。旧完成记录的画像缺失允许保留并显示“历史未记录”，更正其他数据不强制补齐，但已有画像不得清空。旧草稿首次完成按新规则。修改保留原因、版本及审计，合并保留旧JSON字段。


## 7. 手机号、手机、设备与物资

- 分公司必填；直播间、运营、中控、使用人可未分配，支持备用资源。管理写入限老板/本公司负责人，普通员工只读权限内资料。
- 纯执行中控：号码/手机/设备仅本人使用或直接负责，不因同直播间或关联手机卡扩大权限。关联链接也需服务端重查权限。
- 手机号列表：号码、开户人、使用人、状态、绑定抖音/微信/小红书/快手；筛选开户人、使用人、状态等，10/20/50 每页，默认20。
- 号码编辑：运营商四选（电信/联通/移动/网络卡）；月费元、流量 G、主/副卡、正常/停机/注销、用途、备注；旧自定义运营商与套餐文字保留。
- 副卡绑定同公司主卡并共享套餐；不能自指或嵌套；有副卡时调拨/注销/改副卡须先处理关系。
- 所在手机：已编号手机+卡槽，或“其他”个人手机说明，两者互斥。每台两个卡槽，同一号码最多占一个槽；从号码或手机修改都同步关联与版本。
- 手机一机一档、数量1；列表七列为编号、信息、使用人、实际登录抖音、实际登录微信、安置手机卡、状态。
- 实际登录账号与卡的绑定账号不同：抖音现有同公司账号多选，微信多行；换 SIM 不自动更改实际登录记录，旧手机显示未登记，不从 SIM 推断。
- 设备和物资：编号、型号/名称、分类/序列号、数量/单位、购入日期、购入单价、当前单价估值、归属和备注。价款用整数分，旧缺失值保持空，不推算。
- 家具等需要独立标签时逐件建档；旧 2–100 件物资批次可拆成单件，保留来源批次并归档，单件数量1、编号固定；每件可各自分配直播间/人员。拆分不重复计入资产总量。

## 8. 权限实现注意

代码中的 isExecutionController 指“有 CONTROLLER、但无 BOSS 和 OPERATOR”，并不是“只有一个岗位”。所以 CONTROLLER+LEAD_SPECIALIST 仍限制资源修改，但在导粉模块通过专员能力访问本人数据。纯执行中控即使被指定分公司负责人，部分管理函数仍拒绝，属于需核对的组合边界，不能把本文的角色概述当成自动放权许可。

只有主播角色不自动获得当前统计报表权限；当前统计查询主要由老板、负责人、专员、运营范围组成。分公司负责人也不能自动代执行所有账号。确切限制查看权限函数与模块 service，并参考 known-issues.md。

管理工作台分别展示直播数据和打粉数据入口；两者是既有报表的不同视图，仍按原有角色及归属范围查询，不因新增导航授权直播中控查看统计。

### 手机号列表位置展示（2026-09-30）

## D050 老板场次管理（2026-10-01）
- 仅老板可补录历史场次及软删除/恢复。列表提供账号、中控、日期、阶段筛选，10/20/50分页，默认20；中控等原岗位入口与权限保持。
- 补录仅已结束或未正常开播；账号/历史版本/实际中控/时间/原因必填。已有唯一时间对应账号版本时强制一致，无历史匹配时需明确选择。可选历史离职员工，不因当前账号停用或封禁拒绝历史补录。
- 补录不关联虚构上班/登录，不套用当前流程：workflow为空三阶段、workflowVersion=0、progress为空。发生时间独立于系统录入时间。已开播补录可被认领，未开播不可认领。
- 异常下播或未开播须原因与截图；五种下播类型及截图限制沿用D049/D048。补录、修改、删除、恢复均留痕；归属账号不可编辑。
- 仅COMPLETE/CANCELLED可移回收站；有效LeadTask或LiveReport须先软删除。场次删除不级联删除附件、事件、报表；正常列表、可认领列表、冲突计算、班次有效场次排除软删除项。老板只读查看回收站详情与截图，其他岗位不可直接读写删除场次。
- 恢复需核验账号/人员直播区间及原上班范围，无自动关联恢复。导粉任务及报表的写入/恢复也校验父场次未删除。
- 老板上班检查页仅展示员工、上下班时间、检查摘要、上班状态；详情保留四项检查、审计及更正。D046员工上班规则未变。

## D052 人员统计与确定打粉数据（2026-10-02，已上线）

- 每场新增实际主播，准备默认账号绑定主播，允许选择本分公司在职主播；沿用老板可兼任账号岗位的既有规则。开播前必须选定，开播后只由老板填原因更正；不会改账号绑定及历史原始报表人数。
- 报表人员按场次实际主播/实际中控、导粉认领人解析；旧缺项回退已保存的历史人员，无法确定显示未记录。独立旧报表由老板填原因补正。主播变更不赋予主播查看场次或其他人员数据的权限。
- 报表两视图支持账号、主播、中控、导粉、日期组合筛选，合计覆盖全部筛选结果。日期按北京时间实际开播日，跨凌晨不拆场。
- 快捷日期：昨日、近7天、近30天、本月、上月。近7/30天及本月截至昨天，上月为完整自然月；月初本月为空，不反向扩大范围。
- 确定数据独立于逐场导粉数据，仅老板管理；日期+主播+后端唯一，软删除也保留唯一占位，重复时编辑或恢复原记录。可登记同日多后端，保存即向主播展示，没有“整天录齐”审批。
- 后端资料只维护唯一名称和启用/停用，不物理删除；确定数据保存当时名称、主播姓名和两种单价。D053取消链接输入及列表展示，新记录不登记链接，原链接列和历史快照仅保留。未更换后端/主播时编辑继续保留原名称快照。
- 数量为非负整数，有效不超过加人；单价以元输入最多两位小数，整数分存储。总价=有效数量×后端单价，主播提成=有效数量×主播单价，整数精确乘法；服务器仅允许昨天及以前。
- 老板修改/删除/恢复需要原因、版本及原子审计；不自动覆盖导粉记录、不算中控/导粉提成、不代表付款或发薪。
- 主播工作台只查本人有效确定数据，默认本月截至昨天，按天/周/月展示加人、有效、提成及合计。周一至周日，自然月，始终只统计所选区间；无数据日期不造零。主播查询不返回后端、后端价格或其他员工资料。
- 每日对比按日期+主播汇总已完成有效场次及当前所有确定条目；差值=确定-场次，缺任一侧显示未录/无场次而不是零，存在未完成或删除数据的实际开播场次标记不完整，不自动纠正差异。


## D054 不导粉场次（2026-10-02）

- 导粉专员仍认领并选择是否导粉；直播数据填写岗位自D056按新场次快照决定。
- 新提交完成必须明确导粉/不导粉，草稿可暂不选。不导粉仅要求直播指标完整，打粉字段及比例隐藏；填报人不能据此跳过直播时长、画像等校验。
- 旧完成记录允许历史未标记，统计/必填仍沿用原规则，不自动将0推断为不导粉。已有明确选择不能清空，完成后修改必须说明原因并留痕。
- 改为不导粉保留已有打粉人数及历史审计，表格显示不适用，不计入导粉场次/人数/转化率/未完成提示；改回导粉恢复已保存输入并校验完整性。
- 直播报表显示所有场次；打粉报表默认导粉（含历史未标记），可筛选不导粉、历史未标记或全部，切换分页/详情返回保留条件。合计单独显示导粉统计场数。
- 每日对比跳过已明确不导粉的完成报表和草稿，不生成虚假零值；未选择状态的未完成场次仍提示数据不完整。老板确定数据独立保留。
- 旧独立报表可在原打粉更正入口明确状态，原权限/版本/原因/审计不变。中控对打粉数据不增加访问权限；直播数据遵循D056。

## D055 工作台预览与外部主播（2026-10-02，开发中）
- 老板按在职员工预览直播中控、导粉、主播页面；复用实际页面及查询，身份范围取目标员工。预览不创建登录会话、不增加岗位，写操作和截图上传禁止。强制改密的员工尚无可用工作台，选择页说明原因。
- 外部主播独立于员工；姓名/称呼、分公司、状态、备注。老板和所属分公司负责人维护，导粉只选择。已有档案不跨公司改绑，在接收公司另建档案保留原引用；不提供物理删除。账号内部/外部默认主播二选一。历史记录保留当时外部主播关联及姓名。
- 直接填报只用于本人所在分公司的外部主播账号：填写账号、外部主播、北京时间开播时间和场次。开播时必须能唯一匹配该公司外部账号历史，否则先处理历史资料。创建人负责填写完整直播/打粉指标，也可选择不导粉。草稿、完成、更正、负责人纠正、删除恢复都使用版本与审计；不创建中控或上班记录。
- 相同账号和开播分钟，执行场次、报表、直接任务互斥；回收站记录先恢复。实际中控显示未安排，不能伪装为填报人。
- 内部主播使用员工ID，外部主播使用external:ID筛选标识，姓名相同也不合并。确定打粉数据的原金额公式和员工主播本人只读范围保持；每日对比纳入直接记录，排除不导粉，并标记待填直接任务。
- 中控手机号、手机、设备、物资按本分公司且使用人本人可见，只读。所属中控、直播间、卡槽、账号关联不能扩大范围；协作主播/账号/直播间原范围保持。兼任运营或老板的原管理范围保持。此条取代早期“使用人或所属中控”规则。

D055上述规则已于2026-10-02发布生效。外部主播分公司建档后不可直接改动，停用保留历史；新增直接填报要求启用，历史更正不因停用阻断。

## D056 直播数据填写分工（替代一律由导粉填写的规则）
老板设置全公司直播填写岗位，默认导粉；新准备场次记录岗位，旧场次/历史空值继续原流程。外部直接任务和老板补录不受设置影响。中控模式只可在实际下播后填写自己可执行场次的直播指标，支持草稿和留痕更正，不返回打粉指标；直播提交完整方可收尾，既有未收尾禁止下班规则继续有效。未正常开播/取消无需填报。
中控直播提交生成唯一场次报表；导粉认领不再因该报表存在而受阻，直播指标只读、打粉可先存草稿，待直播提交再整体完成。独立版本及白名单更新防止跨岗位覆盖，进房人数和比例实时关联。导粉任务回收只回收打粉部分，保留中控直播数据；恢复要求父场次/直播报表未删除。管理人员沿用权限更正直播数据，旧直播更正接口禁止覆盖新场次草稿。
直播定时事项按场次流程快照/实际开播时间显示中央弹窗，可主动开启无声桌面通知；同一浏览器跨窗口尽量去重，关闭不等于完成。预览不发送通知。浏览器后台节流、休眠或关闭页面时不能保证通知；无后台推送。
