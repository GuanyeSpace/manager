# 导粉专员岗位

## 已确认范围

- 新岗位 `LEAD_SPECIALIST`，显示“导粉专员”，登录进入 `/leads`。原直播中控职责和数据隔离保持。
- 工作按真实直播场次开展，不固定绑定抖音账号；一人可同时认领多场，一场只有一人。只允许本分公司已实际开播的 LIVE/WRAP/COMPLETE 场次，准备中、未正常开播及取消准备不进入认领池。异常中断已实际开播，正常统计。
- 上线前的旧场次 `leadEligible=false`；上线后新建场次默认 true。旧数据不自动认领、不批量重写。未认领只返回场次基本信息，认领后才返回统计数据。
- 粉丝群发卡片时间与频率自行决定，不记录发送动作；开播前线下安排。
- 不允许交接。误认领仅老板或原分公司负责人可纠正，原因必填，已填数据保留，原认领人即时失去访问权。员工离职的待补数据由负责人补齐，原认领归属保留。

## 数据与权限

- 导粉专员只查看和填写本人、本分公司认领数据；运营只读当前负责账号、同分公司的场次；老板全局维护，分公司负责人维护本分公司历史和当前数据；直播中控无统计数据权限。
- 场次归属沿用开播场次来源快照。账号调拨不移动数据，原分公司负责人继续补齐。历史单独报表仍可由老板和对应分公司负责人维护。
- 直播指标沿用原有字段。打粉统计为进粉丝群、链接点击、长按、后端加入、有效人数；多粉丝群按场次汇总，场观沿用进房人数，比例自动计算。
- 新流程没有带货填报字段。历史带货值保留可查，旧打粉表单保存时也保留原带货数值。
- 草稿仅存 LeadTask.data，不把空白指标写成零。所有指标明确、时长大于零且本场实际下播后才可提交完成，发布到已有 LiveReport，保持原报表列表及筛选能力。
- 已完成数据仍可更正，原因必填，不能重新保存成缺项草稿。所有首次填报、草稿修改、完成、更正、误认领纠正、删除和恢复都保存操作者、时间与前后值。旧报表增加可见修改历史。
- 待补允许跨天，不阻止认领新场；显示已下播分钟数，不加超时通知或处罚。
- 导粉专员不能删除。老板/负责人可带原因将整场数据移入回收站或恢复，认领和直播执行记录保留，不能通过删除重新认领。

## 保护与验证

- 认领、人员管理、账号交接、数据修改沿用同一事务管理锁；sessionId 数据库唯一约束兜底。过期版本拒绝提交，前端保留输入。
- 新流程数据统一走导粉场次页面，旧报表编辑、打粉保存和回收站接口禁止绕过统一状态与审计。
- 迁移仅追加岗位、LeadTask 表和 WorkSession.leadEligible，不改写原列数据；测试 `test:lead-migration` 在独立临时测试库验证全部旧列不变与新旧场次默认值。
- `test:leads` 覆盖同时认领、同时编辑、多直播并行、越权、调拨、离职、补填、有效性、历史接口保护、软删除、审计回滚与真实 HTTP；测试使用隔离库并清理本次记录。

## 多岗位兼任（2026-09-28）

员工管理的岗位改为多选，同一个登录账号可以同时勾选“直播中控”和“导粉专员”，也支持其他岗位组合。顶部提供有权访问的工作台入口；切换页面不会结束直播或解除认领。

- 直播中控同时只能负责一场正在直播的场次；导粉认领独立判断，可以同时认领本人或其他直播间的多个实际开播场次。
- 每场只允许一名导粉专员；纯直播中控仍不可查看统计数据。兼任导粉只增加本人认领场次的数据权限；同时任运营时，运营负责账号的数据可查看但不可因此修改他人认领数据。
- 增加岗位保留原账号、直播间和物资绑定。撤销岗位先检查该岗位的职责交接；撤销导粉岗位后不再能查看或填写其导粉数据，记录保留，由有权限的负责人继续维护。
- 岗位变更写入人员审计，旧表单提交会检测岗位是否已被他人更改。在职老板和自我降岗限制继续有效。
- 数据库仅新增 `User.roles` 数组保存兼任岗位，原 `User.role` 保留；旧员工兼任数组为空，不自动分配新岗位。页面统一展示有效岗位的合集，不要求员工理解主次岗位。
- 自动化验证：`scripts/test-multi-roles.ts`、`scripts/test-role-migration.ts`。迁移演练逐表比较 19 张表的所有原字段，验证旧员工岗位不变。多岗位测试覆盖直播中兼任导粉、权限范围、岗位筛选、撤岗、并发修改和双工作台 HTTP 页面。
