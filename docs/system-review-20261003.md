## 1. 应当分清的业务对象

| 对象 | 含义 | 不能与什么混淆 |
| --- | --- | --- |
| 员工/岗位 | 登录身份与多岗位能力；负责人另由分公司指定 | 分公司负责人不是独立Role；岗位不等于账号负责人 |
| 内部/外部主播 | 内部主播是员工；外部主播独立建档不登录 | 不能按姓名合并；外部转内部尚无身份合并流程 |
| 抖音账号 | 当前分公司、绑定人员及设备关联 | 当前绑定主播不等于某场实际主播 |
| AccountRecord | 账号归属/职责历史快照 | 不能用当前人员覆写旧场归属 |
| 直播间 | 场地和资源组织关系 | 不是抖音账号，也不是一场直播 |
| 上班记录 | 登录人的检查及工作时间 | 不是实际代控人员的自动考勤 |
| 执行场次 | 准备、开播、下播、收尾及本场人员快照 | 未正常开播也有记录；不等于直播报表 |
| 导粉认领/直接填报 | 填报负责人、草稿及完成状态 | 外部直接填报不制造中控执行/上班记录 |
| 直播报表 | 已提交指标、人员解析、打粉指标 | 直播已填不等于打粉完成；空值不是0 |
| 确定打粉数据 | 老板按日期+主播+后端保存的结算依据 | 不覆盖逐场填报；总收入不等于已收款 |
| 手机号/手机 | 号码档案与实体设备，卡槽关联 | SIM绑定账号不等于手机实际登录账号 |
| 物资 | 实体单件或旧批次、使用人与估值 | 估值不是折旧会计，也不是员工现金责任 |

## 岗位能力矩阵（业务目标与实际差异分开）

| 身份 | 日常入口/范围 | 可写内容 | 关键限制 |
| --- | --- | --- | --- |
| 老板 | 全公司管理、员工预览 | 员工/组织/账号/资源/流程、场次管理、报表、确定数据、填写岗位 | 预览只读；普通导粉认领仍需导粉岗位；历史补录与正常执行是不同入口 |
| 分公司负责人 | 本分公司业务；暂无独立专属工作台 | 本公司账号/资源/流程/报表 | 不管理员工/分公司、不跨公司、不维护确定数据；兼中控存在A01权限缺口 |
| 运营 | 所负责账号/流程/报表及按现有关系可见资源 | 账号流程与话术 | 统计只读，不因运营岗位取得物资编辑权 |
| 直播中控 | 当前负责账号、本人使用资源、本人上班 | 执行、话术、个人资料；中控模式本场直播指标 | 不维护资源/账号流程，不取得打粉指标权限；代控选择不授予新登录身份 |
| 导粉专员 | 本公司可认领场次、本人已认领/直接任务 | 草稿/提交/留痕更正 | 无普通删除权、不能修改中控模式直播指标；管理员可纠正认领 |
| 员工主播 | 本人的有效确定数据 | 无收入编辑，只读本人提成 | 不返回后端单价/公司总收入/其他主播资料 |
| 外部主播 | 不创建登录 | 无系统操作 | 由导粉/管理方建档与填报，不能与同名员工主播合并 |
| 小助理/财务 | 其他岗位占位入口 | 仅已有具体关联授予的能力 | 当前没有完整财务/工资工作流，岗位名称不代表具有资金权限 |

多岗位能力按合集处理；负责人来自分公司关系，必须单独核验，不能仅凭工作台名称推断权限。平台账号Cookie、自动采集、自动发卡不属于当前已上线链路。

## 2. 端到端业务地图

### 2.1 建档与授权
老板建分公司、员工、多岗位 → 指定分公司负责人 → 建内部/外部主播、直播间与抖音账号 → 分配运营/中控、关联手机号和实际登录手机 → 配置账号流程与话术。
- 人员必须在职且岗位/公司匹配；老板可兼任。
- 一账号一家当前分公司；历史版本独立。账号默认内部/外部主播互斥，中控可空。
- 中控为空的账号可存档，但不能直接走需要中控的执行链；外部账号可走直接填报。
- 登录优先老板→中控→导粉→主播→其他；切换工作台不会切换员工身份。
- 普通员工身份离职撤会话；改岗/调公司检查账号、直播间、资源交接。
- 待核：负责人兼中控权限冲突、离职时未结束上班/历史待办归谁处理、运营与负责人缺独立工作台入口。

### 2.2 中控执行
开始上班 → 四项设备检查 → 到岗确认 → 选择账号/实际中控/实际主播 → 准备清单 → 确认实际开播 → 定时/口令事项 → 五种下播方式 → 下播清单与异常 →（中控填报模式提交直播指标）→ 完成收尾 → 结束上班。
- 未正常开播：原因类型+说明+截图→归档；取消准备：原因→归档；两者不进可认领池。
- 开播前及下播后清单全部完成才允许推进；直播中未完成任务不阻止下播。
- 异常下播说明+截图必需；收尾保留已确认的异常类型。违规封禁下播不会自动封禁账号。
- 正常下班8小时按系统起点；提前下班须原因。都要求四项检查和未收尾处理完。
- 本场登录人、账号责任中控、实际代控是不同字段；当前执行权限仍依赖登录人及当前账号责任关系。
- 流程和话术保留场次快照；修改账号流程只影响未来场次。中控改本场话术同时更新账号后续话术。
- 弹窗只提醒未完成定时事项；关闭不等于完成。桌面授权可选、无后台推送保证。

### 2.3 内部场次填报
公司设置决定**新准备场次**的直播填写岗位。
- 导粉模式：本公司专员认领已实际开播场次 → 保存直播/打粉草稿 → 下播且必填完整后提交 → 报表。
- 中控模式：中控下播后填直播指标→直播报表；专员可先认领、存打粉草稿，待直播指标提交后完成打粉部分→更新同一报表。
- 是否导粉必选：不导粉不要求打粉人数、保留历史值但不展示统计；仍需有人确认不导粉。
- 认领一场一人、一人多场；管理员纠正认领留原因，原人失去编辑权；不会自动分配未认领场次。
- 数据按权限/版本/事务保存；已有完整填报不能用草稿动作退回缺项。

### 2.4 外部主播直接填报
本分公司导粉专员选择启用的外部主播资料及账号→开播时间/场次名→独立直接任务→完整直播/打粉或不导粉→报表。
- 当前账号、历史开播归属均校验；同账号同一分钟与执行场次/报表/直接任务互斥。
- 不安排中控、不生成上班记录；本人填报，管理岗位更正/纠正负责人/回收。
- 明确边界：当前入口只服务外部主播；内部主播无中控时没有同等专员直接建档入口。用户已确认也需要，待扩展。
- 补录早于账号建档的历史数据可能没有匹配AccountRecord；当前会拒绝，不允许静默套当前归属。用户明确不需要此类补录，不新增特殊修复入口。

### 2.5 日统计与确定收入
逐场直播/打粉按北京时间**实际开播日**统计→按人员/账号/日期筛选→老板另录日期+主播+后端确定数据→总收入/主播提成→每天按主播对比差异。
- 同场实际人员由执行记录/认领人解析；更新账号当前人员不替代历史。
- 确定数据独立、多后端合计；后端资料改名/价格变动不自动改历史单价快照。
- 收入=有效数×后端单价；主播提成=有效数×主播单价，整数分计算。
- 默认本月至昨天；近7/30天也截至昨天。周一至周日、自然月，仅汇总选择区间。
- 无记录不补零；差值=确定数据−逐场数据；缺一侧不当0。未完成数据提示完整性，不自动修正。
- 当前不算运营/中控/导粉提成、不记录真实收付款、不锁已结算月份。用户第一批问题确认前不增加这些功能。

### 2.6 资源关联
号码→主/副卡套餐→手机双卡槽；账号→绑定号码；手机→实际登录多个抖音号/多个微信号；资源→分公司/直播间/运营/所属中控/使用人。
- 三者是不同关系；手机账号不从插卡自动推断。
- 一手机号最多一个卡槽、一机两槽；同一号码绑定抖音号受唯一关系约束。
- 纯中控列表/详情按本分公司且使用人本人，关联跳转不扩权；兼运营/管理角色沿用其自身范围。
- 实体物资拆分后单件编号数量1、独立使用人；旧批次留档。
- 待核实际用法：公共备用物资无使用人时如何由中控查看；运营的关联物资可见范围是否符合实际；这是业务讨论项，不自动放宽。

### 2.7 更正、删除和恢复
场次→关联认领/报表→确定数据是不同生命周期。
- 场次只允许归档后软删除，有有效认领/报表需先处理；恢复不自动恢复所有子数据。
- 导粉模式回收任务同步回收报表；中控模式回收导粉只回收打粉部分，直播保留。
- 直播报表回收与打粉回收各有标记；恢复须父场次未删除。
- 确定数据删除不联动逐场报表；对应唯一键仍占位，恢复原记录。
- 原截图、任务旧备注/不适用、审计保留；没有物理清理业务历史的本轮授权。
- 待补浏览器核对：所有组合删除后的页面入口是否足以完成服务端允许的恢复顺序。
