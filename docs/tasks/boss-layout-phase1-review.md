## 必须修复

### R1 / K021 / P2：抽屉跨桌面断点后隐藏但仍锁住页面

位置：components/management-shell-chrome.tsx:149–159，mobileOpen不感知视口，lg:hidden只隐藏Overlay/Content。
复现：390×844打开管理菜单 → 不关闭抽屉直接放大到1366×768。
实测DOM：dialog data-state=open，display=none；body pointer-events=none、overflow=hidden。页面看起来恢复桌面，实际仍被不可见模态层锁定。
修复：到桌面断点必须真正关闭/卸载模态状态并释放滚动、焦点和指针拦截；不能只改CSS显示，也不能把Dialog改为非模态来绕过问题。监听视口时正确清理监听，不放宽lint。
验收：窄屏打开→桌面→窄屏，抽屉应保持关闭直到主动打开；桌面能点击链接、Tab切焦点并正常滚动，没有隐藏模态残留。

### R2 / K022 / P2：浏览器前进会恢复旧抽屉

位置：components/management-shell-chrome.tsx:125–128。
复现：桌面依次进入员工/boss/users、分公司/boss/branches → 调至390px → 打开抽屉 → 浏览器后退到员工页（抽屉隐藏）→ 浏览器前进到分公司页。
实测：前进后dialog重新可见。原因是openedAt仍保存旧navKey，返回同URL时再次相等；注释声称“任何跳转包括前进后退自动收起”不成立。
修复：路由离开时失效的打开状态不能在历史返回后复活。采用简洁的状态生命周期方案；不仅测试通过菜单点击的导航，要覆盖浏览器历史和同布局查询参数变化。
验收：后退/前进后一直关闭；重新主动打开仍可用；Esc、遮罩、关闭按钮及菜单选后关闭继续通过。

### R3 / K023 / P2：多岗位老板重复切换入口及侧栏超出视口

位置：components/workspace-switcher.tsx:8–9、app/layout.tsx:29和components/management-shell-chrome.tsx:135–148及顶栏WorkspaceMenu。
复现：隔离老板增加CONTROLLER和LEAD_SPECIALIST岗位，1366×768刷新/boss。
实测：根布局的绿色“工作台切换”条与管理顶栏切换按钮同时显示；sidebarTop=51、sidebarBottom=819、viewport=768，侧栏底部需滚动整页才能露出。单纯高度偏差有旧实现因素，但重复切换入口是这次新顶栏带来的，属于本轮布局验收范围。
证据截图：/tmp/manager-review-multi-role-20261001.png（隔离数据，未提交）。
修复：管理布局实际出现时只展示顶栏切换；其他工作空间保留原有岗位切换。不要简单按hasRole(BOSS)全局隐藏，老板兼职仍可能进入其他执行布局；依据实际布局或一致的展示边界处理。允许最小修改根布局/全局切换组件的展示协调，不改变workspaceLinks及权限函数。解决高度计算，不用写死51px补丁（窄屏条可换行）。
验收：纯老板、老板+直播中控+导粉、纯中控/导粉分别检查；管理页仅一套切换，非管理工作台原切换可用；1366×768菜单独立滚动到最后，不依赖整页滚动补出底部。
